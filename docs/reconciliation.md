# 模拟盘对账与恢复

## 状态

- `healthy`：账户可读取、本地快照存在、所有本地未完成或未知订单均可由远端确认；
- `degraded`：关键状态缺失，但尚未确认冲突；禁止下单；
- `blocked`：存在无法确认订单或明确不一致；禁止下单；
- `unknown`：远端账户本身不可读取；禁止下单。

## 启动顺序

```text
读取公共品种规则
  -> 私有账户与挂单同步
  -> 保存账户快照和远端挂单
  -> 查询本地未完成/unknown 订单
  -> 比较本地快照与远端余额、持仓
  -> 计算对账状态
  -> 仅 healthy 允许进入模拟盘下单链
```

订单提交后先重新同步账户，再次比较余额、持仓和订单。任何 `unknown` 都会保留，不会被当作失败或成功猜测。撤单前也先对账；撤单后远端状态无法确认时停止。

## demo-doctor

`demo-doctor` 检查本地配置、实盘关闭、模拟标志、数据库、公共时间、品种规则、凭证、私有鉴权、账户同步、挂单、恢复和下单门禁。

没有凭证时，公共项仍真实执行；凭证项为 `BLOCKED`，私有项为 `SKIPPED`，`order_allowed` 为 `BLOCKED`，进程退出码为 2。

## 私有 WebSocket

当前代码提供模拟盘私有登录签名、只读状态连接、订单/账户/持仓事件适配器和 `PrivateStateMonitor`。`DemoTradingSession` 先完成 REST 账户、现货挂单和衍生品持仓同步及首次对账，再启动私有连接；未确认全部订阅时禁止人工测试订单。

私有持仓推送只作为暂态。最终对账会调用 REST 持仓接口；REST 返回任一非零衍生品持仓时，现货测试订单保持禁止，不会通过忽略 WebSocket 状态绕过安全检查。

账户和持仓推送先转换为领域暂态，按事件时间拒绝旧消息覆盖新消息，并标记 `needs_reconciliation=1`。周期 REST 对账成功后才确认暂态。对账不健康会停止私有流。私有推送不是最终事实源。
